# BIOX - Project Instructions

## Overview

BIOX is an educational software engineering project built to explore modern software development practices through a realistic healthcare domain.

The project uses laboratory exam analysis as a complex business scenario to practice frontend engineering, backend architecture, artificial intelligence, Retrieval-Augmented Generation (RAG), document processing, and scalable system design.

Although the domain is healthcare, the primary goal of BIOX is **software engineering excellence**, not creating a medical product.

* avoid unnecessary abstractions
* write self-documenting code
* keep modules independent

---

# Engineering Principles

Every feature should follow these principles:

## Single Responsibility

Each module should solve one problem.

## Modularity

Business domains should remain independent.

## Separation of Concerns

UI, business logic, persistence, AI and infrastructure should remain separated.

## Deterministic Core

Business calculations must always produce deterministic results.

## AI as an Assistant

Artificial Intelligence supports the user experience.

It does not replace deterministic business logic.

---

# AI Responsibilities

Artificial Intelligence should be responsible for:

* explaining laboratory results
* summarizing trends
* identifying correlations
* generating natural language reports
* answering user questions
* improving user experience

AI should **never** be responsible for:

* calculating medical scores
* executing business rules
* replacing deterministic algorithms
* inventing scientific evidence

Whenever possible, AI responses should be grounded using Retrieval-Augmented Generation (RAG).

# Code Generation Guidelines

Whenever code is generated:

* Prefer TypeScript.
* Use meaningful names.
* Keep functions small.
* Prefer pure functions.
* Avoid duplicated logic.
* Avoid magic numbers.
* Favor readability over clever implementations.
* Generate production-quality code.

Comments should explain intent, not implementation.

---

# Git Workflow

The project follows atomic commits.

Each commit should represent a single idea.

Examples:

* docs(project): redefine project vision
* docs(domain): define patient domain
* feat(api): create patient module
* feat(web): implement dashboard layout
* refactor(score): simplify calculation engine

Documentation, architecture and implementation should evolve together.
